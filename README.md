# DeepSeek Chatbot: Fine-Tuning vs RAG

This project investigates and compares two major approaches for customizing large language model (LLM) outputs in chatbot development:

1. **Fine-Tuning** – training distilled versions of the DeepSeek-R1 model to mimic an existing chatbot’s style.  
2. **Retrieval-Augmented Generation (RAG)** – enriching prompts with relevant, retrieved context before passing them to the model.

The work aims to replicate the **Brother David Bot** (an OpenAI + RAG chatbot) on **consumer hardware**.

---

## 📜 Overview

- **LLMs Used**: Distilled DeepSeek-R1 models (`8B` and `14B` parameter variants).  
- **Methods**:  
  - Fine-tuning on datasets generated by either the OpenAI-based Brother David Bot or DeepSeek-R1+RAG.  
  - Implementing a RAG pipeline using the original bot’s retrieval system.  
- **Tools**:  
  - [Ollama](https://ollama.com) – local LLM hosting & inference.  
  - [Unsloth](https://unsloth.ai) – efficient LoRA fine-tuning on limited hardware.  
  - Python – for implementation, data generation, training, and benchmarking.

---

## 🔬 Key Findings

- **Performance**
  - **Fine-tuned models** were **faster** than base/RAG models due to shorter outputs and omission of DeepSeek’s `<think>` block.
  - RAG added **minimal latency** despite longer prompts.

- **Quality**
  - Fine-tuning improved **language consistency** (German-only responses) and **semantic similarity** to the original bot.
  - RAG improved factual accuracy but lacked stylistic mimicry.
  - Fine-tuned models convincingly imitated style but **hallucinated facts/quotes**.

---

## 📊 Benchmarks

Metrics used:
- **SemScore** – semantic similarity to control responses.  
- **LangScore** – probability of correct language output.  
- **Word Overlap** – lexical similarity.  
- **Time/Token Stats** – prompt length, generation time, and total latency.

---

## 📌 Conclusion

- **Fine-tuning**: Best for local deployment & stylistic mimicry, but prone to hallucinations.  
- **RAG**: Best for dynamic, up-to-date knowledge integration, but less style-consistent.  
- **Hybrid approach** could offer the most robust chatbot design.
